# Decision & Assumption Log

Every assumption [A] and non-obvious decision made while building the app per `docs/PRD.md` is logged here.

| # | Area | Decision / Assumption | Rationale |
|---|------|----------------------|-----------|
| D-01 | Docs | The PRD was moved from the repo root (`PRD-Project-Scheduling-App.md`) to `docs/PRD.md` | The build prompt says "Build the app in docs/PRD.md"; PRD is the source of truth |
| D-02 | Stack | Prompt requests "Livewire 3"; installed `livewire/livewire ^4.4` (latest stable compatible with Laravel 13) | Livewire 3 does not support Laravel 13; v4 keeps the same component API for everything used here (Alpine included). Can pin `^3` if an older Laravel is used later |
| D-03 | Database | MySQL database `project_scheduler`, charset `utf8mb4`, engine InnoDB; dedicated user `project_scheduler`@`localhost` (never root), credentials only in `.env` (gitignored) | Prompt requirement; XAMPP MariaDB 10.4 confirmed available |
| D-04 | Tests | Default test run uses SQLite `:memory:` (`phpunit.xml`); `composer test:mysql` runs the same suite on MySQL via `phpunit.mysql.xml`, which overrides only `DB_CONNECTION`/`DB_DATABASE` — credentials come from `.env` | Prompt requirement |
| D-05 | Engine | Scheduling engine lives in `app/Domain/Scheduling/`: pure PHP value objects + `ScheduleEngine::calculate()` as the **one** recalculation entry point. No Eloquent, facades, HTTP, or `Illuminate` imports anywhere in that namespace | Prompt rule + PRD §8.6 |
| D-06 | Engine | Working-day math: ISO weekdays 1 (Mon) – 7 (Sun). Duration counted in working days; task end = start + (duration − 1) working days. A start date on a non-working day is moved forward to the next working day (TSK-1 AC) | PRD §8.1–8.3 |
| D-07 | Engine | Dependency semantics: FS with lag L ⇒ successor starts `L + 1` working days after predecessor's finish (L = 0 ⇒ next working day; L = 2 ⇒ two working days after finish, per DEP-2/4 AC). SS with lag L ⇒ successor starts `L` working days after predecessor's start. Negative lag (lead) allowed; FS lag −1 means starting the same day the predecessor finishes | PRD DEP-2/3/4 + [A] negative lag |
| D-08 | Engine | Multiple predecessors: effective start = max of (adjusted requested start, all predecessor constraints) (DEP-6) | PRD §8.2 |
| D-09 | Engine | Parent (summary) tasks are never scheduled directly: start = earliest child start, end = latest child end (TSK-4). Dependencies pointing **to or from** a parent are expanded to all descendant leaf tasks (PRD §8.5 [A]) — mathematically identical to constraining against the parent's window | Keeps forward/backward passes leaf-only and cycle-free |
| D-10 | Engine | A task flagged/used as a parent but currently having **no children** is treated as a normal task (defensive default) | Avoids empty-window ambiguity |
| D-11 | Engine | Default start for a task without `start_input`: the earliest requested start among project tasks; if none exists, today's date (then adjusted to a working day) | Deterministic and matches the primary scenario (PRD §11) |
| D-12 | Engine | Slack = working days between early start and late start; critical ⇔ slack = 0. Multiple critical paths fall out automatically (CPM-5). Parent slack derives from min child late finish | CPM standard; PRD CPM-2/3/5 |
| D-13 | Integrity | Circular dependencies are rejected at the application layer before save with a message naming the cycle (DEP-5), and the engine additionally throws if fed a cyclic graph (defense in depth, PRD §8.7). DB enforces FKs, unique predecessor→successor pair, and CHECK-style enum domains; app validation mirrors all of it | Prompt rule "integrity in both DB constraints and application validation" |
| D-14 | Recalc | Any change to projects, calendars, holidays, tasks, or dependencies triggers a full-project recalculation (CAL-5, CPM-6, PRD §8.6) via Eloquent observers + explicit calls from UI actions; writes use quiet updates to avoid recursion. All scheduling values are persisted (`effective_*`, `early_*`, `late_*`, `slack`, `is_critical`) so views only read | Single entry point; views never compute dates |
| D-15 | Calendar | One calendar per project, auto-created on project creation (PRJ-1 AC) with defaults [A]: Mon–Fri working, 8 h/day, Sat/Sun weekend. `weekend_days` is derived from working days (stored for display). Holidays live in the `holidays` table (date + optional end date, CAL-3); the legacy `calendars.holidays` JSON column is kept in sync but the table is the source of truth | PRD CAL-1/2/3 |
| D-16 | Salary | `resources.salary` uses the `encrypted:integer` cast, is in `$hidden` (never serialized to JSON), is never logged, and is only stored — not used for cost (RES-4, PRD §3 Non-Goals). Migration column widened from bigint to `text` because encrypted values are ciphertext strings | Prompt rule + PRD |
| D-17 | Salary | RES-5 (hide salary from views): implemented as a session-scoped UI preference toggle on the resources page (no login in MVP, so no per-user DB setting) | Prompt: no login in MVP |
| D-18 | Scope | P1 items that would require **new third-party dependencies** are not built (prompt: "Do not add dependencies without asking"): PDF/image export (GNT-6, PRT-4) and drag-to-edit Gantt (GNT-5). Ideas recorded in `docs/SUGGESTIONS.md` | Prompt rule overrides PRD priority |
| D-19 | Scope | CAL-4 (Indonesian national holiday import) ships as a curated static **template** of well-known national holidays (fixed-date observances + July 17, 2026 substitute for Aug 17 falling on Saturday); clearly labelled "verify against the official SKB list" before use | PRD asks for a template, not guaranteed-official dates |
| D-20 | Scope | TSK-7: indent/outdent buttons are implemented; copy/paste of tasks is deferred to `docs/SUGGESTIONS.md` (no-dep simple version is possible but low value vs. risk; PRD P1) | Scope control |
| D-21 | Locale | UI language: English + Indonesian via `resources/lang/{en,id}/app.php`; switcher stores choice in session; default `en` [A] | PRD §9, prompt |
| D-22 | Data | Priority stored as the PRD labels `Low/Medium/High/Critical`; milestones are `duration = 0` (TSK-5); percent complete 0–100 (TSK-6) | PRD |
| D-23 | Seed | Only fake seed data (`DatabaseSeeder`, "Website Redesign" / Acme Corp, fake people). No real personal data | Prompt rule |
| D-24 | Viz | Gantt and PERT are rendered as server-side SVG computed in Livewire component PHP (layout geometry only — all dates/slack/critical flags come from persisted engine output). No charting library added | Prompt: no JS scheduling logic, no unapproved deps |
| D-25 | Resource Chart (additional feature) | **Additional feature: Resource Chart** — a report-only workload view per member over time, built outside the PRD scope. Assumptions [A]: (a) it **never moves tasks** — no resource leveling, it only reports; (b) pure calculator in `app/Domain/Workload/` next to the scheduling engine, same purity rules as D-05 (no Eloquent/facades/HTTP, deterministic); (c) only leaf tasks count — parent tasks are excluded from load and from the unassigned series; (d) a task assigned to several members counts fully for each member (no splitting); (e) load(day) = Σ allocation of active tasks (allocation percent per assignment, default 100); capacity = 100 on working days, 0 on weekends, holidays and the member's leave days; (f) overallocated ⇔ load > capacity, so a task spanning a weekend/holiday (capacity 0) is flagged on those days — work sitting on a non-working day is surfaced as a conflict, and the chart shades non-working columns like the Gantt; (g) leaveConflict ⇔ member on leave AND an assigned task active that day; (h) week/month aggregation = peak (max) and average (mean of daily loads over the calendar days of the period inside the calculated range), ISO week keys; (i) leaf tasks with no assignment are reported in a separate "unassigned" series (each counts the default 100%); (j) members = union of assignment and leave member ids; (k) calculation is redone on every page load from persisted engine output — no stored workload state, so any change to tasks/dependencies/calendar/leave/assignments is reflected automatically | Feature request (explicitly not in docs/PRD.md); reporting-only scope keeps PRD non-goal "no automatic resource leveling" intact; recomputing on load reuses the D-14 single recalculation entry point without new triggers |
